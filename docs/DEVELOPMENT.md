# 构建与开发补充说明

本文档补充说明 Lyria STUDIO 桌面端工程边界、构建约束与本地测试方式。

## 工程切换与数据保护

- **原文与译文独立**：演唱原词与中文译文分开保存。常规 OCR 配对台按左（只读画面识别参考）、中（导入译文）、右（独立导入原文）组织；仅右栏参与和译文的对应操作，应用后支持整步撤销，不改写原识别参考和已有受保护主轴。
- **模式切换确认**：从原词打轴切换至画面 OCR 时，若当前工程已有原词内容，界面提示选择归档保留、作为参考或取消切换，不静默清空磁盘文件。
- **多选区 OCR 属性**：支持画布拖拽与缩放管理最多四个字幕选区；修改选区名称、说话人或样式时，可按需选择仅作用于后续识别或同步现有条目中仍由该选区管理的属性。

## Windows 构建约束

- 独立打包入口为 `build_windows_qt.ps1` 与 `LyriaQt.spec`，需要预先在本地准备完整的 `resources/` 运行资源目录（包含 FFmpeg、RapidOCR 模型、Tesseract 及对应驱动/加速组件）。
- 请勿将个人字幕工程、音视频素材、API 密钥、本机缓存或临时输出放入打包输入目录。
- 第三方运行时组件与对应源码归属约束见 [THIRD_PARTY.md](THIRD_PARTY.md) 与 [二进制组件与源码对照清单](THIRD_PARTY_BINARIES.md)。

## 隔离测试与存储目录

- 运行桌面实窗自动化测试时，Windows 下可通过 `tools/private_desktop.py` 在独立虚拟桌面启动测试进程，避免抢占当前前台桌面。
- 应用默认在程序相邻 `profiles/` 目录读写用户设置与崩溃恢复资料，亦可显式传入 `--storage-dir <目录>` 重定向至指定测试目录。
